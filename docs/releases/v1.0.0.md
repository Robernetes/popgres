The first popgres release: a fork of PocketBase v0.40.6 that runs on PostgreSQL 17+.

## Highlights

- **PostgreSQL storage** with the PocketBase REST API, JSON responses, filters and the official JS and Dart SDKs. The differences are listed in [COMPATIBILITY.md](https://github.com/Robernetes/popgres/blob/v1.0.0/docs/COMPATIBILITY.md).
- **Multiple instances** behind a load balancer, coordinated through Postgres (`POPGRES_CLUSTER`).
- **Row level security**: the collection API rules are compiled to Postgres RLS policies for the direct SQL clients, with an optional strict mode for the API.
- **Realtime from the database** with the Postgres logical replication (`POPGRES_REALTIME_SOURCE=replication`), including the changes made outside of the API.
- **Vector search**: the pgvector `vector` field, `POST /api/collections/{collection}/vector-search` and the `@vectorDistance` sort.
- **MCP server** (`/mcp`, disabled by default) with tools generated from the collections.
- **Embedded Postgres for development**: `popgres serve --dev` without a `DATABASE_URL`.
- **`popgres-import`** to migrate a PocketBase `pb_data` directory (see [MIGRATING.md](https://github.com/Robernetes/popgres/blob/v1.0.0/docs/MIGRATING.md)).

## Downloads

- `popgres_1.0.0_<os>_<arch>.zip`: the server (no SQLite driver).
- `popgres-import_1.0.0_<os>_<arch>.zip`: the PocketBase importer.

## Compatibility and versioning

popgres follows semantic versioning from this release. The compatibility target is the PocketBase v0.40.6 REST API and the JS SDK 0.28.x. Requirements: PostgreSQL 17+ with `pgcrypto` (and `vector` for the vector fields), and the `CREATEROLE` attribute for the app role (or the RLS roles created by an administrator).
