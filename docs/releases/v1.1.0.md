A hardening release for the production deployments: the cluster, the realtime replication, the row level security for the direct SQL clients, the backups, the operations and the release supply chain.

## Upgrade notes

Read these before upgrading from v1.0:

1. **Stop all the instances before starting v1.1.** The cluster messages are now signed with a secret stored in the database, so the v1.0 and v1.1 instances can't exchange messages. Start the v1.1 instances once all the v1.0 ones are stopped.
2. **Direct SQL clients (breaking):**
   - `popgres_rls.set_claims` accepts only the new short-lived RLS tokens instead of the API auth tokens. Get one with `POST /api/rls/token` (15 minutes by default); the API rejects them, so a token that leaks from a database session can't be used against the API.
   - The external roles read only the records allowed by the **list** rule (before: the list or the view rule), so a `SELECT` can't read all the records of a "view only by id" collection.

   See [RLS.md](https://github.com/Robernetes/popgres/blob/v1.1.0/docs/RLS.md).
3. **Docker:** the image runs as the non-root user `popgres` (uid/gid 10001). A data directory or volume created by a previous image (owned by root) must be made writable by it:

   ```bash
   docker run --rm -u 0 -v popgres_data:/app/popgres_data --entrypoint chown popgres -R 10001:10001 /app/popgres_data
   ```

## Highlights

- **Cluster:** the messages are signed and their channel can't be guessed by the other database roles; the instances compare their cached collections and settings with the database after a reconnection, a lost message and every minute; the realtime events have their own dispatch queue; a dead replication leader releases the leadership in about a minute; the client requests are forwarded only to the connected instances.
- **Realtime replication:** large transactions are streamed in batches instead of kept in memory, the slot is created with `FAILOVER` (Postgres 17+), and the instances warn about a missing or unconsumed slot and about mixed realtime sources.
- **Backups:** the restore recreates the RLS roles and privileges (also on a new server), and the temporary cluster tables are not dumped.
- **Operations:** the readiness check `GET /api/health?ready`, the cluster counters and the pool stats in the superusers health data, `POPGRES_DB_MAX_CONNS` and `POPGRES_DB_CONN_MAX_LIFETIME`, a 5 seconds lock timeout for the collection changes, and the new [OPERATIONS.md](https://github.com/Robernetes/popgres/blob/v1.1.0/docs/OPERATIONS.md) guide (health checks, poolers, several databases on one server).
- **Security fixes:** the vector search `filter` accepts the `@collection.*` and `@request.*` fields only from the superusers (the same as the records list), and the MCP schema resource doesn't list the superusers only collections to the other users.
- **Performance:** the realtime access checks of the guests with the same subscription options run once per record event.
- **Fixes:** the views that use another view collection are kept when the fields of that collection change.
- **Merging PocketBase:** the new [UPSTREAM.md](https://github.com/Robernetes/popgres/blob/v1.1.0/UPSTREAM.md) guide describes the changes to the PocketBase code and how to merge a new PocketBase version.

The full list is in the [CHANGELOG](https://github.com/Robernetes/popgres/blob/v1.1.0/CHANGELOG.md).

## Downloads and verification

- `popgres_1.1.0_<os>_<arch>.zip`: the server (no SQLite driver).
- `popgres-import_1.1.0_<os>_<arch>.zip`: the PocketBase importer.
- An SPDX SBOM for each archive (`*.zip.sbom.json`), and `checksums.txt` with its Sigstore signature bundle `checksums.txt.sigstore.json`.

This is the first signed release. Verify a download with [cosign](https://docs.sigstore.dev/cosign/system_config/installation/):

```bash
cosign verify-blob --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github.com/Robernetes/popgres/\.github/workflows/release\.yaml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

The compatibility target is still the PocketBase v0.40.6 REST API and the JS SDK 0.28.x, with PostgreSQL 17+.
